Screens A--E identify graph encoders that solve the fixed \texttt{bus14}
control problem well, but their action heads cannot be moved to WCCI: each
output row names one action from the source action list. This chapter isolates
the reusable part of those policies. The \texttt{bus14} encoder is retained and
frozen, its action heads are discarded, and new WCCI heads are learned. Screen
F and Chapter~\ref{ch:screen-f-transfer} address the stricter case in which the
encoder and action-selection interface are transferred together.

\section{Question and hypotheses}
\label{sec:encoder-transfer-question}

The main question is whether a graph encoder learned on \texttt{bus14} provides
more useful WCCI features than a target encoder without source training. A
second question is whether the corrected inputs of
Chapter~\ref{ch:encoder-inputs} make those features more reusable. The study
therefore separates three effects:

\begin{enumerate}
  \item source pretraining versus random encoder features;
  \item original inputs (NL) versus corrected inputs (NLS);
  \item frozen source features versus an architecture trained end to end on WCCI.
\end{enumerate}

The four transferred representations come directly from Screens D and E:
\texttt{e0n0v0}, \texttt{e1n0v0}, \texttt{gbi\_lbi}, and
\texttt{ga2b\_lb2a}. They share the decisions retained from Screens A--C:
GINE, two message-passing layers, width 128, and energized/max global readout.
The two Screen-D variants test whether same-substation edges improve reuse; the
two Screen-E variants test whether bidirectional or asymmetric asset relations
produce more reusable representations.

\section{Transferred components and controls}
\label{sec:encoder-transfer-design}

The frozen block contains the node and edge input projections, type embeddings
when present, GINE layers, normalization layers, and any learned representation
projection before the grid-specific action head. The source action heads are
removed. Each WCCI agent receives a newly initialized head with the target
action dimension. The centralized critic is also newly initialized and remains
trainable because it is target-specific.

The random-frozen route is the key diagnostic for representation transfer. A
source-frozen actor may learn something through its new heads even if the
encoder features are arbitrary. The source encoder provides evidence of reuse
only when it improves on that control. The fully trainable scratch route gives
the target performance available when the same architecture is allowed to
adapt end to end.

The NL route uses the preprocessing under which the existing Screens A--E
checkpoints were trained. The NLS route retrains the same \texttt{bus14}
architectures with the corrected physical inputs, then uses exactly that NLS
preprocessing on WCCI. Scaling is never switched only at deployment, because a
frozen encoder must receive the input convention on which its weights were
learned.

\section{Interpretation rules}
\label{sec:encoder-transfer-interpretation}

The result is interpreted through matched comparisons rather than the largest
single endpoint:

\begin{itemize}
  \item If both NL and NLS frozen encoders beat random frozen, the source GNN
  has learned reusable features; an NLS advantage then measures the additional
  effect of corrected preprocessing.
  \item If only NLS beats random frozen, compatible preprocessing is necessary
  for the learned representation to cross grids in frozen form.
  \item If a pretrained frozen encoder beats random frozen but remains below
  target scratch, the representation transfers partially but still benefits
  from target adaptation.
  \item If pretrained frozen and random frozen are indistinguishable while
  target scratch learns, the architecture can fit WCCI but the source features
  show no useful frozen transfer under this protocol.
\end{itemize}

With one training seed, these statements remain descriptive. The strongest
claim should be based on the matched difference from random frozen and on
consistent learning-curve behavior, not on a small difference between
unrelated endpoints.
